# Stylus documentation

Stylus helps early-stage teams turn evidence into experiments, decisions,
execution and learning. Start here without needing the internal development history.

- [Self-hosting](SELF_HOSTING.md): prerequisites, installation, migrations and production basics.
- [Development](DEVELOPMENT.md): tests, isolated SQL, CI and contribution workflow.
- [Architecture overview](ARCHITECTURE_OVERVIEW.md): Core, Marketing and public boundaries.
- [Integrations](INTEGRATIONS.md): connecting accounts versus configuring a deployment.
- [AI](AI.md): optional ModelGateway providers and bounded workflows.
- [Demo](DEMO.md): optional fictional evaluation workspace.
- [Privacy](PRIVACY.md) and [security](../SECURITY.md): operator responsibilities and disclosure.
- [Licenses](THIRD_PARTY.md), [asset provenance](ASSET_PROVENANCE.md) and [contributing](../CONTRIBUTING.md).
- [Beta release notes](RELEASE_NOTES.md) and [release audit](RELEASE_AUDIT.md): tested environments and remaining gates.

Detailed implementation references include [Boards](BOARDS.md),
[Core execution](CORE_EXECUTION.md), [growth and learning](GROWTH_LEARNING.md),
[database](DATABASE.md), [plugins](PLUGINS.md) and [worker operations](WINDOWS_WORKER.md).

Engineering records—PROJECT_STATE, CODEX_TASKS, DECISIONS and the redesign
specifications—describe implementation history and are useful for maintainers.
They are not prerequisites for evaluating or installing the product.
